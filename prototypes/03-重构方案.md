# 03 发展党员全流程管理 · 两级页面重构方案（确认稿）

> 目标：解决当前单页「内容混乱不清晰 + 排版大量空白」，对齐 PRD 3.2.2 的输入项/输出项/异常处理，保持全站 IBM Carbon + 党建红（--brand-red #C21F30）视觉一致。
> 实现方式：**单文件双视图 + URL hash**（`03-发展党员.html` 内部切换 `#overview` / `#person-<id>`），不改 8 处导航 repoint。

---

## 1. 信息架构总览（两级 Drill-down）

```
┌─ 1级 概览页 (#overview) ──────────────── 看全局：汇总 / 台账 / 预警
│   KPI 汇总卡 → 流程全景步骤条(标准模板·只读) → 进度台账 → 超期预警清单
│                         │  台账每行「查看详情」
│                         ▼
└─ 2级 人员详情页 (#person-<id>) ──────── 办业务：该人员全链路
    面包屑返回 │ 流程进度区 │ 办理操作区 │ 档案材料区
```

设计原则：**概览页只"看"不"办"**（无当前节点/校验清单/时间轴/归档包）；**详情页只"办"某个人**（不含全局汇总）。两级各司其职，消除单页信息无层级导致的"混乱"。

---

## 2. 1级 · 概览页（#overview）

区块清单（单列流式，统一最大宽度容器 ~1180px 居中，杜绝宽屏断裂留白）：

1. **页头**：标题「发展党员全流程管理」+ 操作按钮（新建流程 / 导出归档包）。
2. **KPI 汇总卡**（5 项，复用现有）：在库发展对象 / 进行中 / 本月待公示 / 超时预警 / 本年已转正。
3. **流程全景步骤条**（标准 25 节点模板，**只读**）：标注五阶段分组、4 处法定公示★；**各阶段角标显示"在办人数"**（取 LEDGER 聚合）；点击某阶段 → 下方台账按阶段过滤。**注意：此处是制度全景，不是某个人的进度**，避免与 2级个人步骤条概念重复。
4. **发展党员进度台账**（复用 LEDGER）：多人员列表（姓名/阶段标签/当前节点/进度条）；每行「查看详情」→ 下钻 `#person-<id>`。
5. **节点超期预警清单**（复用 WARN，全局跨人员）：党委审批 3 个月 / 谈话 1 个月 / 公示 5 工作日时效，红橙分级。

> 布局要点：概览页**不采用 `1fr 360px` 双列**（这正是当前空白根因），改为单列分区 + 内部按内容成对（如预警可独立全宽）。分区用小标题区隔「数据 / 流程 / 台账 / 预警」层级。

---

## 3. 2级 · 人员详情页（#person-<id>）

面包屑「发展党员全流程管理 / 张* 发展详情」→ 返回 `#overview`。进入时默认选中该人员当前节点。

**分区一 · 流程进度区**
- 个人步骤条（高亮当前节点，复用 NODES 单人视图；与 1级"全景模板"区分：此处显示该人员已办/在办/待办状态）。
- 流程时间轴（复用 timeline：已归档节点不可改）。

**分区二 · 办理操作区**（核心"办"区）
- 当前节点信息卡（含**节点级输入项** genericForm：申请材料/思想汇报/考察意见/证明材料/表决结果，分色标签；表决结果点「发起表决」弹 modalVote 自动校验到会/赞成）。
- 提交前校验清单（复用 checklist：6 类关键规则，默认拦截失败项置灰）。
- 异常处理（退回 / 终止 / 公示异议，confirmOp 弹窗含审计留痕说明；该人员若命中超期预警，顶部红条提示）。
- *关键自动校验规则演示*：**降级为可折叠说明**（`<details>` 或 toggle），置于本区底部，不再独立占一张卡（消除冗余与留白）。

**分区三 · 档案材料区**
- 全套发展党员材料归档包（复用 ARCHIVE 16 项 + genArchive 一键生成/下载）。

> 布局要点：详情页采用**单列三分区**，仅"流程进度区"内部用双列（步骤条 / 时间轴 天然成对）；其余单列。三区用分隔线 + 小标题，信息密度一致，避免再次出现双列高度错位留白。

## 4. 路由、状态与导航

- 单文件 `03-发展党员.html`：JS 控制 `showView('overview' | 'person', id)`；初始化读 `location.hash`（`#overview` 默认 / `#person-0`）。
- 下钻：台账行 `onclick="showView('person', 0)"` + `location.hash='#person-0'`；面包屑返回 `#overview`。
- **导航 repoint 保持不变**（8 处指 `03-发展党员.html`，03 自身 active 不变）——单文件方案无需改链接。
- 人员数据：新建 `PERSONS`（或并入 LEDGER）承载 id/姓名/当前节点/阶段进度，详情页按 id 取数；默认示例 5 人（张*/李*/王*/赵*/陈*）。

## 5. 数据 / 代码迁移（最大化复用，降风险）

| 复用 | 用途 |
|---|---|
| `NODES`（25节点 + inputs） | 全景步骤条(只读) / 个人步骤条(状态) |
| `LEDGER` / `WARN` / `ARCHIVE` | 1级台账/预警、2级归档包 |
| `renderStepBar / renderChecklist / renderTimeline / renderLedger / renderWarnList / renderArchive` | 渲染 |
| `genericForm / confirmOp / openVote / submitVote / finishGongshi` | 详情页办理交互、流程下推 |
| **新增** | `showView` 视图切换、`PERSONS` 人员数据、步骤条"模板态/个人态"双渲染、详情页三区骨架 |

**删除**：原 `work-layout`（`1fr 360px` 双列，空白根因）、原"六类规则卡"独立位置（改折叠）。

## 6. 视觉规范（解决空白与层次）

- 全站统一 `--card-gap`；概览页单列 + 居中最大宽度，避免宽屏视觉断裂。
- 分区标题（section heading）区分"看 / 办"层级，用户一眼分清全局与个办。
- 详情页三区密度一致，双列仅用于天然成对内容（步骤条+时间轴）。

## 8. 风险 / 待确认项

1. 2级是否需支持 5 人真实切换数据？→ 方案按 id 取 PERSONS，默认张*，其余人员下钻展示各自当前节点/进度（示例数据）。
2. 归档包 / 预警是否需在 2级局部展示？→ 建议：该人员命中超期预警时，在"办理操作区"顶部红条提示，归档包仅 2级档案区出现（与 PRD 输出项③一致）。
3. 1级"流程全景步骤条"是否要支持点击阶段联动台账过滤？→ 建议支持（轻量），增强概览可操作性。
