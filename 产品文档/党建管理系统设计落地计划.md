# 党建管理系统设计落地计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已审核的党建管理系统视觉与交互规范，落地为可评审、可交接的 PC 管理端、党员移动端和党委驾驶舱页面设计资产。

**Architecture:** 以 `outputs/党建管理系统页面结构交互说明与视觉规范.md` 作为唯一需求基线。先建立全端共用的视觉令牌与组件状态，再按 P0→P1 的顺序设计页面，并以业务规则、权限、留痕和异常状态作为每个页面评审准则。

**Tech Stack:** 设计工具不限（Figma、即时设计或 Axure）；页面交付采用 PNG/PDF 预览与 Markdown 交互说明；本计划不包含前端代码实施。

## Global Constraints

- 管理端基准宽度为 1440px，左侧导航 216px、顶部栏 64px、内容区外边距 24px、卡片间距 16px。
- 使用党建红 `#C21F30` 作为品牌与关键动作色，不以大面积红色承载常规内容。
- PC 管理端、移动端和驾驶舱必须共用状态颜色：红色风险、橙色提醒、蓝色处理中、绿色完成、灰色非活跃。
- 所有涉及敏感数据、审批、导出和归档的页面必须提供权限、状态或审计反馈。
- 不设计 PRD 未定义的业务规则；党员移动端不承载批量维护与复杂配置。

### Task 1: 建立视觉基础与组件总览

**Files:**
- Read: `outputs/党建管理系统页面结构交互说明与视觉规范.md`
- Create: `design/01-foundations-and-components.pdf`
- Create: `design/01-foundations-and-components-notes.md`

**Interfaces:**
- Consumes: 设计规范第 2、5、6 节。
- Produces: 色彩、文字、间距、图标、状态标签、按钮、输入框、筛选区、表格、摘要卡、流程时间轴、附件区、空状态的设计基线，供 Task 2–5 复用。

- [ ] **Step 1: 建立颜色与文字样式**

在设计工具中创建如下样式并命名：`Brand/Primary #C21F30`、`Status/Risk #C21F30`、`Status/Warning #D97706`、`Status/Info #2D6DB5`、`Status/Success #2E8B57`、`Surface/Page #F5F6F8`、`Surface/Card #FFFFFF`、`Text/Primary #1F2329`、`Text/Secondary #6B7280`。创建 20/16/14/12px 四级文字样式。

- [ ] **Step 2: 完成状态组件**

绘制红、橙、蓝、绿、灰五种 Tag；每种提供“短标签”“带图标标签”和“带说明提示”三种样式。文案分别使用“逾期”“待完善”“进行中”“已归档”“草稿”。

- [ ] **Step 3: 完成通用工作台组件**

绘制待办卡、指标卡、组织树、筛选区、数据表格、详情摘要卡、流程时间轴、附件区和空状态。数据表格必须包含固定表头、行内操作、批量选择和分页；时间轴必须包含节点、办理人、时间、意见和附件。

- [ ] **Step 4: 视觉自检**

检查所有组件：正文最小字号为 12px；主操作仅使用品牌红；状态不只依赖颜色且具有文字；卡片圆角在 4–8px；内容区白底与 `#F5F6F8` 页面背景对比清晰。

- [ ] **Step 5: 输出与评审**

导出 `design/01-foundations-and-components.pdf`，并在 `design/01-foundations-and-components-notes.md` 记录颜色、字号、间距和每种组件状态。评审通过后再进入页面设计。

### Task 2: 设计 PC P0 首页、组织与党员页面

**Files:**
- Read: `design/01-foundations-and-components.pdf`
- Create: `design/02-pc-workbench-org-member.pdf`
- Create: `design/02-pc-workbench-org-member-notes.md`

**Interfaces:**
- Consumes: Task 1 的通用组件与设计规范第 4.1、4.2 节。
- Produces: 首页工作台、组织树与组织档案、党员名册、党员档案和发展党员页面，供 Task 3 的流程页面沿用。

- [ ] **Step 1: 设计首页工作台**

使用 1440px 桌面画板，绘制 216px 左导航和 64px 顶栏。内容区依次放置四张指标卡（待办审批、即将逾期、红色预警、本月完成率）、我的待办、重点预警、工作日历、三项趋势图和常用功能。每个待办与预警提供点击后的目标页面名称。

- [ ] **Step 2: 设计组织树与组织档案**

左侧树展示党委→党总支→党支部→党小组四级层级，右侧展示组织概览、班子成员、党员概况、任期倒计时和沿革记录。为“组织撤销”补充禁用状态，文案为“该组织下存在未办结流程，请处理完成后再操作”。

- [ ] **Step 3: 设计党员名册和档案**

名册设计组织范围、身份、党籍状态、流动状态和积分区间筛选；表格展示姓名、所属组织、党员身份、入党时间、党费状态、学习完成率、积分。档案页使用人员摘要卡和基础信息、党籍信息、组织生活、学习、党费、奖惩、异动、操作记录 8 个 Tab；身份证号与手机号以脱敏值展示。

- [ ] **Step 4: 设计发展党员流程**

绘制申请入党、培养考察、发展对象、接收预备、转正归档的五阶段步骤条；右侧固定流程时间轴。创建“材料缺失”和“培养期不足 12 个月”两种校验状态，提交按钮置灰并显示具体原因。

- [ ] **Step 5: 页面验收**

逐页检查：管理员能在首页两步内进入 P0 页面；所有敏感信息均脱敏；组织调整、核心字段变更和档案导出均显示二次验证入口；不存在无状态的强流程节点。

### Task 3: 设计 PC P0 组织生活与党费页面

**Files:**
- Read: `design/01-foundations-and-components.pdf`
- Create: `design/03-pc-orglife-fee.pdf`
- Create: `design/03-pc-orglife-fee-notes.md`

**Interfaces:**
- Consumes: Task 1 组件、设计规范第 4.3、4.5 节。
- Produces: 组织生活和党费两条 P0 业务链路的列表、详情、归档、预警与台账页面。

- [ ] **Step 1: 设计组织生活计划与活动列表**

提供“日历/列表”双视图，活动列表字段为会议类型、主题、时间、签到率、台账完整度、当前状态。对频次不足、待审批和即将开展事项使用对应状态标签。

- [ ] **Step 2: 设计活动详情与台账归档**

活动详情包含基本信息、参会签到、会议资料、纪要与影像四个 Tab；右侧展示操作时间轴。台账页使用“完整度清单 + 台账预览 + 导出区”，缺少时间、地点、主持人、记录人、应到/实到、议题、决议或影像时，归档按钮禁用。

- [ ] **Step 3: 设计党费概览与缴费明细**

概览放置本月应缴、实缴、收缴率、欠缴人数与趋势。缴费明细按组织、月份、缴费状态筛选，并提供“催缴”“登记线下缴费”两个受权限控制的动作。

- [ ] **Step 4: 设计欠缴催办与收支公示**

欠缴页面展示连续欠缴月数、最近催办记录和处理结果，对连续 6 个月未缴使用红色预警。收支公示展示流水、票据附件、审批时间轴、季度公示预览和导出操作记录。

- [ ] **Step 5: 页面验收**

检查组织生活是否完整覆盖计划→执行→归档；检查党费页面是否清晰区分应缴、实缴、减免、补缴与欠缴；检查每个导出入口都有日志提示。

### Task 4: 设计党员移动端 P0 页面

**Files:**
- Read: `design/01-foundations-and-components.pdf`
- Create: `design/04-mobile-member-p0.pdf`
- Create: `design/04-mobile-member-p0-notes.md`

**Interfaces:**
- Consumes: Task 1 的颜色、字体与状态组件，设计规范第 4.7 节。
- Produces: 党员个人高频任务的移动端页面与交互说明。

- [ ] **Step 1: 设计移动端首页与待办**

首页顶部展示姓名、所属支部和本月积分；主入口固定为待办、签到、学习、党费。待办页按“今日待办、即将截止、已完成”分组，只展示本人事项。

- [ ] **Step 2: 设计签到与学习**

签到页提供二维码、人脸、定位三种由活动配置决定的状态；成功、超出围栏、活动未开始三种反馈需独立绘制。学习页展示课程进度、剩余时长、随机答题和心得提交，不提供倍速或拖拽进度控件。

- [ ] **Step 3: 设计党费与个人中心**

党费页展示本月应缴金额、支付入口、历史凭证和欠缴提醒。个人中心提供脱敏档案预览、请假申请、消息和设置；不设计组织配置、批量导出或批量操作。

- [ ] **Step 4: 移动端验收**

在 390px 宽度画板检查：主操作触达区域不小于 44px；状态有文字说明；个人档案和缴费记录不显示非本人信息；从首页到签到、学习、缴费均不超过一次主入口点击。

### Task 5: 设计党委驾驶舱与 P1 管理页面

**Files:**
- Read: `design/01-foundations-and-components.pdf`
- Create: `design/05-dashboard-and-p1.pdf`
- Create: `design/05-dashboard-and-p1-notes.md`

**Interfaces:**
- Consumes: Task 1 的图表与状态样式、设计规范第 4.4、4.6、4.8 节。
- Produces: 党委领导查看的综合驾驶舱及学习、考核 P1 页面。

- [ ] **Step 1: 设计党委数据驾驶舱**

采用深蓝灰背景；顶栏展示党徽、系统名称和统计时间。顶部使用党组织总数、党员总数、本月组织生活数、当月党费收缴率四项指标。左区组织与党员结构，中区三项趋势与年度达标仪表盘，右区排行与预警数量，底部红色滚动预警栏。

- [ ] **Step 2: 设计学习教育页面**

设计学习任务、进度督导、资源库和考试管理。任务卡展示主题、截止时间、覆盖范围、完成人数；督导页可按组织下钻并突出低完成率组织；考试页区分自动评分和待人工阅卷。

- [ ] **Step 3: 设计监督考核页面**

设计党员积分、支部考核、整改闭环和预警清单。积分页区分基础分、加分、扣分与申诉；整改项必须展示责任人、期限、状态和销号记录；预警清单可以按风险等级和责任组织筛选。

- [ ] **Step 4: 图表与权限验收**

检查驾驶舱颜色不只表达风险，所有图表具有标题、单位与统计时间；检查图表点击后明确标注下钻目标页面；检查领导端不出现可直接修改业务数据的按钮。

在 `outputs/党建管理系统设计交付清单.md` 按端、模块、页面、优先级、当前状态列出全部设计资产；P0 页面必须包括首页、组织与党员、发展党员、组织生活、党费、移动端首页/待办/签到/学习/党费。

- [ ] **Step 4: 评审结论记录**

在交付清单末尾记录每项结论为“通过”“需修改”或“延期”；“需修改”必须包含页面名称、问题、责任人和再次评审日期。
